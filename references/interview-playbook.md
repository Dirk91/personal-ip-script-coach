# Interview Playbook

Use this playbook only after `SKILL.md` selects 逐步共创, or when 生成完整版 still needs one decisive fact. The interview is adaptive, not a questionnaire.

## Non-negotiable turn rule

**每轮最多一个问题。** A normal turn contains:

1. 一到两句话确认本轮真正挖到的内容；
2. when useful, one short note about where it belongs in the script;
3. one next question, and no second question hidden in a list or parenthesis.

If the user replies `1`, `继续`, `可以`, or an equivalent short confirmation, treat it as consent to进入下一步. Do not ask them to repeat the confirmation in a fuller sentence.

## Working gap table

Maintain this table mentally or in working notes; do not dump it on the user every turn.

| Dimension | Evidence to seek |
|---|---|
| Content goal | The one primary result: follow, consult, save, comment, convert, or another stated goal |
| Target audience | Who should recognize themselves immediately |
| Pain scene | A visible moment, constraint, behavior, or consequence |
| Core claim | What the audience should believe by the end |
| Real case | A person, message, client, project, or event that demonstrates the problem |
| Personal proof | Why this creator can credibly speak: lived experience, result, work, or repeated observation |
| Change mechanism | What action, choice, or understanding changed the result |
| Action path | What the viewer can do next in concrete terms |
| Product bridge | Who should follow, use a course, seek a service, or request one-to-one help |
| Voice | Phrases, rhythm, humor, intensity, and roughness that sound like the creator |

## Default priority

Unless the user's answer changes the main line, ask in this order:

1. goal;
2. audience;
3. pain scene and real case;
4. creator experience and proof;
5. mechanism;
6. action path;
7. product or follow bridge;
8. expression details.

This order is provisional. Re-rank it after every material answer. If the user says a question is not the point, stop that branch immediately.

## Build a good question

A good next question:

- closes one high-priority gap;
- asks for a person, time, place, action, object, number, consequence, or exact line of dialogue;
- reuses the user's own vocabulary;
- does not plant the desired conclusion;
- does not require the user to turn the answer into copy first.

Useful prompt shape:

> 不用组织成文案，就按你平时说话的方式讲：当时具体发生了什么？

Avoid bundled prompts such as “who was it, when was it, how did you feel, and what happened next?” Pick the one missing detail that matters most.

## Decide whether to follow up

Follow up on the same gap when:

- the answer gives only a conclusion, not an event;
- a person appears but nothing happens;
- a result appears but the cause is unknown;
- a number lacks a meaningful before-and-after comparison;
- an emotion has no visible action or detail;
- the case does not yet support the main claim.

Stop and move on when:

- the material can already carry its intended paragraph;
- more detail would pull the script away from its main point;
- the user says the branch is unimportant;
- the material is only a transition and does not need a method;
- the user rejects the premise or direction.

## Capture original language

After every answer, retain in working notes:

- confirmed facts and facts needing verification;
- distinctive phrases worth using verbatim;
- people, actions, objects, dialogue, numbers, and scene details;
- the function of the material in the script;
- the next highest-priority gap.

Clean obvious transcription errors and empty mechanical repetition. Do not replace a concrete event with a polished abstraction, and do not flatten oral rhythm into symmetrical AI-style sentences.

## Provisional draft requests

If the user asks to “压一个看看”, “先写一版”, or otherwise wants an early view:

1. provide a clearly labeled provisional draft using only confirmed material;
2. state the two or three gaps that still prevent completion;
3. accept corrections as new high-priority instructions;
4. resume with one question when the user asks to continue.

An early draft is a checkpoint, not permission to fabricate connective tissue.

## Input fallbacks

### Complete draft

Diagnose existing strengths and gaps first. In 逐步共创 mode, ask about the highest-impact missing material rather than rewriting immediately.

### 语音逐字稿

Treat false starts and repeated words as transcription material, not as a finished structure. Extract claims, stories, and original phrases, then mark the task as **从素材建立初稿**.

### 零散素材 or topic only

Do not reject the input for lacking a draft. Mark the task as **从素材建立初稿**, identify the most important missing foundation, and ask one question.

### Mixed draft and fragments

Keep the draft as the spine, map fragments to possible sections, and interview only for unresolved gaps.

### User refuses numbers

Respect the refusal. Ask for a specific person, scene, action, object, or consequence instead of forcing quantification.

### User wants immediate generation

Generate a provisional version from confirmed material, label uncertain claims, list missing evidence, and never fill the holes with invented details.
