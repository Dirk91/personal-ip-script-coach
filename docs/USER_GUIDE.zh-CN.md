# 个人 IP 爆款脚本引导挖掘 Skill：完整使用说明

Version: 1.0  
Applies to: `personal-ip-script-coach` v0.1.2 and later

## 一、它解决什么问题

这套 Skill 不替你编故事，也不靠固定模板硬凑“爆款”。它先判断稿子真正缺什么，再一次只问一个问题，把你脑中的真实经历、场景、判断、数字和原话逐步挖出来，最后整理成仍然像你本人说话的口播稿。

适合：

- 已有稿子，但内容空、案例少、可信度弱；
- 只有选题、录音或零散素材，不知道怎么组织；
- 希望 Agent 引导自己说，而不是直接代写；
- 需要在 Codex、Claude Code、WorkBuddy、豆包或其他文件型 Agent 中复用同一流程。

不适合：

- 要求虚构个人经历、客户结果、收入数字或聊天记录；
- 要求保证爆款、涨粉、成交或平台审核通过；
- 要求在未获授权时处理他人的隐私、商业秘密或受版权保护内容；
- 把未经人工核验的 AI 输出直接用于医疗、法律、金融等高风险决策。

## 二、开始前准备

至少准备下面任意一种材料：

1. 一篇已有口播稿；
2. 一个选题和若干零散想法；
3. 一份语音逐字稿；
4. 一个真实案例、评论或私信截图；
5. 你自己的内容标准、历史脚本或表达语料。

上传前先处理隐私：隐藏头像、昵称、账号、联系方式、订单号、公司机密和无关元数据。只有在确有必要且获得授权时，才向第三方平台上传真实材料。

## 三、安装与加载

### Codex

把整个仓库放入 Codex 可读取的 Skills 目录，或直接在仓库中工作：

```text
使用 $personal-ip-script-coach。先只诊断这篇口播稿缺什么，不要直接重写。
```

### Claude Code

用 Claude Code 打开仓库，并明确要求读取根目录的 `CLAUDE.md`：

```text
请读取 CLAUDE.md，并按 personal-ip-script-coach 的规则，一次问我一个问题。
```

### WorkBuddy

上传完整 ZIP，然后发送：

```text
先解压并读取根目录 PROMPT.md，再读取 SKILL.md；按其中规则执行。现在进入逐步共创模式。
```

### 豆包

网页对话可能不接受 ZIP。分别上传：

1. `PROMPT.md`
2. `SKILL.md`
3. `references/interview-playbook.md`

然后发送：

```text
先读取并遵守已上传的三个文件。现在进入逐步共创模式。整条回复最多出现一个问号，最后只索取一个信息点。
```

### 其他 Agent

能读取文件时，先读 `PROMPT.md`，再进入 `SKILL.md`。不能读取文件时，复制 `PROMPT.md` 的 “Concise fallback” 段落，并粘贴待处理素材。

## 四、三种工作模式

### 模式 A：只诊断

适合先看问题，不希望立刻改稿。

```text
这是我的稿子。先只诊断：已经有什么、关键缺什么、优先补哪一项。不要改写，不要进入访谈。
```

你会得到：已有优势、关键缺口、优先级和下一步建议。

### 模式 B：逐步共创

适合让 Agent 引导你自己说出内容。

```text
按逐步共创模式处理。先诊断，然后每轮只问一个问题。我回答后，你再决定下一问。
```

正常节奏是：确认上一轮有效信息 → 说明它放在稿子哪里 → 只问一个新的事实。

### 模式 C：生成完整版

适合素材已经够用，或者你明确接受临时版。

```text
用已经确认的素材生成完整版。保留我的原话和具体事件，不要补写未经确认的事实。若仍有关键缺口，标记为临时版并单独列出。
```

## 五、标准工作流程

1. **提供材料**：稿子、逐字稿、选题或案例。
2. **选择模式**：只诊断、逐步共创或生成完整版。
3. **确认标准**：有自己的视频标准就一并提供；没有则使用仓库默认标准。
4. **逐轮补充**：一次回答一个问题，不需要组织成文案，尽量讲真实动作、现场语言和具体数字。
5. **及时纠偏**：Agent 理解错时直接说“这不是重点”，并给出真正核心；它应立即废弃旧方向。
6. **生成与核验**：完成后检查事实、隐私、语感、CTA 和平台风险，再决定是否发布。

用户回复 `1`、`继续` 或 `可以`，默认表示确认并进入下一步。

## 六、怎么回答，效果最好

不要先替自己总结大道理。优先回答：

- 当时具体发生了什么；
- 谁做了哪个动作；
- 现场说了哪句话；
- 有什么物件、时间、地点或数字；
- 你当时最直接的感受是什么；
- 事情发生前后，结果有什么变化。

原话越具体，最终稿越像你；信息越抽象，最终稿越容易变成通用 AI 文案。

## 七、常见故障

### Agent 一次问了很多问题

直接回复：

```text
废弃上一轮多问题输出。只保留当前最高优先级的一个信息点，并用一句话提问。
```

### Agent 开始编案例

直接回复：

```text
删除所有未经我确认的人物、数字、结果和对话。素材不足就标成缺口，不允许虚构。
```

### Agent 把原话改得太工整

直接回复：

```text
故事段落尽量恢复我的原话，只清理影响理解的转写噪音，不要改成排比句或标准 AI 文案。
```

### Agent 声称读过文件，但实际没有

让它复述文件中的一个明确规则。无法复述时，重新上传文件或直接粘贴 fallback，不要继续假设它已经加载成功。

## 八、发布前检查

- 所有人物、数字、结果和对话都能追溯到用户提供或确认的材料；
- 已获得截图、客户案例、录音和第三方作品所需授权；
- 已隐藏不必要的个人信息；
- 没有把可能性写成确定结果；
- CTA 与视频目标一致；
- 口播读起来仍像本人，而不是模板化文案；
- 已人工检查目标平台的最新规则。
